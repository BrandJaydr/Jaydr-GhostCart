## 📋 TRIPLE PASS IN ACTION

Every task runs through 3 mandatory passes:

```
PASS 1: UNDERSTANDING (Read 3x, extract requirements)
   → Formulate plan
   → Map affected files
   → Identify constraints

PASS 2: VERIFICATION (Check everything)
   → Logic verification
   → Security review (SQL inject, XSS, CSRF, etc.)
   → Code quality check
   → UX/UI review
   → Document updates planned

PASS 3: COMPLETENESS (Final polish)
   → All requirements addressed?
   → All edge cases covered?
   → Nothing misunderstood?
   → Ready for execution?

Result: Bulletproof plan before any code written
```

## 🔄 HOOKS IN ACTION

System automatically triggers on events:

```
CODE_WRITTEN
  ├─ Oracle runs tests (must pass)
  ├─ Tests fail? Forge debugs
  ├─ Errors logged automatically
  └─ Loop until passing

VULNERABILITY_DETECTED
  ├─ Red Ranger blocks execution
  ├─ Logs to /.logs/vulnerabilities.md
  ├─ Requires security approval
  └─ Cannot proceed without fix

TOKEN_LIMIT_APPROACHING (70%)
  ├─ Janitor alerts
  ├─ Start wrapping up
  └─ Prepare for handoff

TOO_MANY_TURNS (>20)
  ├─ Task too complex
  ├─ Split into sub-tasks
  ├─ Queue remaining work
  └─ Create detailed TODO
```

## ⏰ SCHEDULER IN ACTION

```
TASK START
  ├─ Load context (2 min)
  ├─ Execute work (15-20 min)
  ├─ Complete + test (5 min)
  └─ Documentation (3 min)

CHECKPOINTS
  ├─ 10 min: On track?
  ├─ 20 min: Completable in 10 min?
  └─ 25 min: Stop if no

TOKEN MANAGEMENT
  ├─ 70%: Start wrapping
  ├─ 80%: Complete current file
  ├─ 90%: Stop immediately
  └─ Save state to /tasks/todo.md

INCOMPLETE WORK
  ├─ Create TODO in /tasks/todo.md
  ├─ Include @agent:next-agent handoff
  ├─ Add full context
  ├─ Note next steps
  └─ Queue for later
```
